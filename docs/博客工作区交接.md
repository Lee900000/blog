## 日常写作

```sh
npm ci
npm test
npm run build:tago
npm run server -- --port 4000
```

文章放在 `source/_posts/`。不要直接编辑 `public/`，因为它是构建产物，会在下一次构建时被覆盖。

所有新增图片（包括封面、插图和截图）都须先通过 [TinyPNG](https://tinypng.com/zh) 压缩，再放入博客源码使用。压缩后检查图片能够正常显示、截图文字清晰；如果无法使用 TinyPNG 或压缩影响内容，应告知用户，不要直接使用未压缩图片。

新增文章后先运行 `npm run routes:prepare`。此命令只为新文章分配随机地址，更新文章 permalink 和正文中的旧文章链接；已有地址始终保留。`article-routes.json` 是源码内的稳定映射，不得删除、重置或复制到公开目录。源码文件名和 legacy_id 仅用于维护，可以保留数字。

构建后运行 `node tools/verify-article-routes.mjs`，检查全部公开文章、搜索索引、站内链接与旧路由排除。发布工具也会执行该检查。历史 migration 目录保留原始抓取路径作为来源证据，重新导入旧资料后须再次运行 `npm run routes:prepare`，不能直接发布旧路径。

随机地址不是访问权限控制；公开文章仍可由归档和搜索找到。旧评论系统如果按 URL 关联评论，新地址可能需要单独迁移评论，本次不修改评论服务数据。旧数字链接和搜索引擎中的旧收录会失效。

## 安全发布

先提交已经审阅的源码变更，并确认工作区干净：

```sh
git status --short
npm run publish:kary -- --confirm Lee900000/blog
```

1. GitHub CLI 当前账号必须是 `Lee900000`。
2. Git `origin` 唯一目标必须是 `https://github.com/Lee900000/blog.git`。
3. 必须输入完整确认词 `Lee900000/blog`。
4. 源码工作区必须干净。
5. 全量测试和根域构建必须成功。
6. 构建产物不得包含文章 `237`、`704`。
7. 远端默认发布分支必须是当前提交的祖先，拒绝非快进推送。

不要强推；发布工具只推送源码，`public/` 不能进入源码仓库。
