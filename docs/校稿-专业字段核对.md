## A. 确定错误、误导性例子或错误来源

### A1 · pro-record-368、547：冲击买卖价须按订单簿方向命名

- 问题：368、547 都以主动买入扫卖盘为例，却没有说明该例对应的是 **Impact Ask Price（冲击卖价）**。368 的提醒仅说“方向应核对”，读者仍容易把主动买入均价叫冲击买价。
- 368 定义替换：“冲击买价（Impact Bid Price）是在规定取样金额下，假想主动卖出、逐档吃掉买盘得到的平均价格；冲击卖价（Impact Ask Price）则是假想主动买入、逐档吃掉卖盘的平均价格。买、卖说的是盘口报价的方向，不是下单人的动作。”
- 368 算例替换：“假设取样金额为 200 USDT，买盘第一档 100 USDT 有 1 枚、第二档 98 USDT 有足够数量；假想卖出先得到 100，再卖出 100÷98 枚，冲击买价约为 98.99 USDT。假想买入扫卖盘算出的则是冲击卖价。”
- 547 算例替换：“假想主动买入两枚，分别吃到卖盘的 100 和 102 USDT，平均成交价为 101 USDT；按资金费公式的术语，这是冲击卖价（Impact Ask Price），不是冲击买价。”
- 证据：[Binance 资金费 FAQ 第 6、7 节](https://www.binance.com/en/support/faq/detail/360033525031)分别在 Bid/Ask 侧取平均；[OKX 资金费机制](https://www.okx.com/en-sg/help/perps-funding-fee-mechanism)分别列出 Bid、Ask 订单簿的计算表。上述 200 USDT 为自设算例，不是平台当前真实取样参数。

### A2 · pro-record-371：产品风险评级被写成个人仓位排队优先级

- 问题：定义“仓位……相对优先程度”、算例“盈利较多且杠杆较高”，以及来源 `Position-ADL-Quantile-Estimation`，实际解释了另一个概念，与本条“自动减仓风险评级”所对应的 Binance 产品级 `adlRisk` 不同。
- 替换文字：“Binance 的 `adlRisk` 是某个合约产品整体的自动减仓风险评级，返回 `high`、`medium` 或 `low`，文档说明每 30 分钟更新。它综合保险基金、持仓集中度、盘口深度、波动等因素，用来提示这个市场发生 ADL 的风险；它不告诉你个人仓位排在第几位。个人仓位排队要另看 `adlQuantile`。”
- 算例：“BTCUSDT 显示 high，是该产品整体评级较高；不能因此把自己仓位的 ADL 灯直接设为最高档，也不能理解成一定马上被减仓。”
- 来源应换成 [Binance Market Data / ADL Risk](https://developers.binance.com/en/docs/catalog/core-trading-derivatives-trading-usd-s-m-futures/api/rest-api/market-data#adl-risk)，对应 `GET /fapi/v1/symbolAdlRisk`。对照：[个人仓位 ADL 分位](https://developers.binance.com/docs/derivatives/usds-margined-futures/trade/rest-api/Position-ADL-Quantile-Estimation)，`GET /fapi/v1/adlQuantile` 返回 0–4、30 秒更新。

## E. 来源维护建议

当前来源组中的 OKX market/book 等链接多只落到大型分类页，不能支持每个细节。修订时应按具体字段/端点定位，如盘口频道、K 线、Get balance、Get positions。Binance 旧文档 URL 现在多重定向到合并后的 API 页面，链接可继续访问不等于原来的标签足够精确；每个来源标题仍需写出接口名和路径。

最小修订顺序：先修 A1/A2/A3/A4/A5/A6/A7，再补 B 中会影响读单位和选择接口的内容；C 中缺少项目资料的词条改成明确待定义，不以任意教学故事补齐业务机制。
