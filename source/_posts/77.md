`nginx 重定向`常用两个配置 `rewrite` 与 `return` 。

## rewrite 命令

使用方法：

```c
rewrite 正则表达式 替换目标 flag标记
```

flag标记可以用以下几种格式：

```c
last – 停止处理后续rewrite指令集，跳出location作用域，并开始搜索与更改后的URI相匹配的location，URL地址不变
break – 停止处理后续rewrite指令集，不会跳出location作用域，不再进行重新查找，终止匹配，URL地址不变
redirect – 返回302临时重定向，浏览器地址栏会显示跳转后的URL地址，爬虫不会更新URL
permanent – 返回301永久重定向，浏览器地址栏会显示跳转后的URL地址，爬虫会更新URL
```

示例：

```c
if ($http_host = www.test.com) {
  rewrite (.*) http://test.com$1;
}
```

# return 命令

`return`是`rewrite`模块里的执行，执行阶段是`rewrtie`，可以写在 `server`、`location`、`if` 里面。

使用方法：

```c
return code [text];
return code URL;
return URL; # 不带返回码，默认返回302临时重定向
```

示例：

```c
if ($http_host = www.test.com) {
  return 301 http://test.com$args;
}
```

# 实际应用场景

## 需求1：

需要将原有 v1 路径重定向到 v2 去，比如 [http://127.0.0.1/v1/details/134](http://127.0.0.1/v1/details/134) 重定向到 [http://127.0.0.1/v2/details/123](http://127.0.0.1/v2/details/123)

nginx 配置

```c
server {
  listen       80;

  # 重定向配置
  location ~* /v1/details/(.+) {
    return 301 /v2/details/$1;
  }
}
```

## 需求2：

由于历史原因，还有如下路径 [http://127.0.0.1/page/l/?s=11&c=22&id=134](http://127.0.0.1/page/l/?s=11&c=22&id=134) 也需要重定向到 [http://127.0.0.1/v2/details/134](http://127.0.0.1/v2/details/134)

从路径来看，以上 `/page/p/` 是公用路径，通过参数不同来实现页面，跟很多的 `MVC` 框架控制路由思路大致一样。

所以这儿不能使用路由来匹配了，需要通过请求参数来重定向，配置如下：

```c

server {
  listen       80;

  # 重定向配置
  location ~* /v1/details/(.+) {
    return 301 /v2/details/$1;
  }

  location ^~ /page/p/ {
    set $flag 0;
    if ($arg_c = 22) { # 表示请求参数 c === 22 时候，设置 flag 为 *1
      set $flag "${flag}1";
    }
    if ($arg_s = 11) { # 表示请求参数 s === 11 时候，设置 flag 为 *2
      set $flag "${flag}2";
    }
    if ($flag = "012") {
      return 301 /v2/details/$arg_id; # 如果以上两个 if 全部命中，则地址重定向
    }
  }
}
```

添加以上配置，重启 nginx 之后，即可开启对应地址的 \`301 重定向。
