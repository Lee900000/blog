## 接入成本如何理解

这里的“低 / 中 / 高”不等于月度账单，而是一次真实接入会遇到的综合成本：**数据模型迁移、应用改造、上线后运维与团队学习**。

- **低**：已有 SQL/协议/驱动经验，数据模型接近，托管服务也成熟。
- **中**：需要新建数据同步链路、索引或 Schema 设计；需要补监控、备份、容量治理。
- **高**：需要改业务模型或事务边界，并引入分布式、数据湖、专用集群或多套运维体系。

真正的云成本仍须按区域、存储、计算、流量、备份与支持等级报价；不在这里用一组脱离条件的价格误导自己。

## 版本怎么看：最新不等于主流

下列表格的版本快照截至 **2026-10-29**。`最新`只写官方已正式发布（GA）的最新线；`主流`写更常见、兼容性更成熟或仍在长期支持中的生产线。它不是市场份额，也不是“必须立刻升级”的建议。托管服务没有可由用户选择的服务端版本时，会明确写成“持续托管更新”，不伪造一个版本号。

## 消息与流处理：让数据流动，不保存最终账本

## 一个更接近日常业务的组合

```text
交易 / 订单 / 账户      →  MySQL 或 PostgreSQL（最终事实）
热点读取 / 限流         →  Redis（加速层，不是账本）
业务事件 / CDC          →  Kafka、Pulsar 或 RocketMQ（传输层）
实时聚合 / 行情 / 日志   →  ClickHouse 或 AnalyticDB（分析层）
离线数仓 / 历史计算      →  MaxCompute、BigQuery、Snowflake 等（数仓层）
全文搜索 / 日志检索      →  Elasticsearch 或 OpenSearch（检索层）
```

先问“最终事实在哪”“数据是否要回放”“查询是按主键还是扫历史”“是否真的需要跨地域一致性”，再看排行榜，产品才不会被错放到不擅长的位置。
