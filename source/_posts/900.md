> **文章定位**：这是一篇面向交易者的机制笔记，不构成投资建议，也不对任何平台或事件作违法、操纵或“伪造价格”的结论。不同平台、合约、保证金模式与风险参数并不相同；遇到争议时，唯一可靠的做法是按时间戳核对规则、价格输入与处理记录。

“仓位被平了”至少可能指三件不同的事：你主动成交平仓、触发止损，或风控系统接管并强平。前两者由你的委托决定；最后一种则由**标记价、账户权益、维持保证金和平台的清算规则**共同决定。

这篇文章想回答的不是“哪家平台一定公平”，而是：当仓位消失、被减仓、或结算价格让人无法理解时，究竟应该要求看到什么证据。

![合约强平与风险处理机制示意图](/assets/liquidation-guide/liquidation-risk-engine.jpg)

## 先把四个价格和两条线分开

| 名词 | 它回答什么 | 交易者最容易误解的地方 |
| --- | --- | --- |
| 最新成交价 | 此刻最后一笔成交是多少 | 一笔很小的异常成交可能失真，很多平台不会直接用它触发强平。 |
| 指数价 | 多个现货或参考市场的价格组合 | 必须知道来源、权重、异常来源如何剔除。 |
| 标记价 `Pm` | 风控计算当前认定的价格 | 这是多数永续合约计算未实现盈亏、触发强平和触发止损的价格口径。 |
| 强平价 `Pl` | 在当前规则和余额下，仓位可能被接管的阈值 | 它不是永久不变的：资金费、手续费、全仓其他仓位、档位和追加保证金都会让它变化。 |
| 维持保证金 `MM` | 仓位继续存活所需的最低权益门槛 | 它不是“开仓保证金的一小部分”这么简单；大仓位常会进入更高的风险档。 |
| 破产价 `Pb` | 仓位权益接近归零时的理论边界 | 它通常不是实际成交价，也不等于用户页面展示的强平价。 |

在本地合约公式资料的正向 USDT 本位框架中，未实现盈亏与方向 `d` 可以抽象为：

```text
d = +1（多）或 -1（空）
pnl = (Pm - Po) × n × contract_value × d
权益 = 余额 + 未实现盈亏 + 已实现盈亏 - 费用
MM = 仓位价值 × 维持保证金率 - 本档速算额
```

当权益触及维持保证金，强平引擎会开始处理仓位；当仓位在市场上无法以足以覆盖亏损的价格处理，才会进入风险基金、对手方减仓等更靠后的环节。实际公式、取整、费率和档位必须以你交易的那一份合约规则为准。

> 公式资料同时提醒了一个很重要的工程事实：同一个“强平价”若以开仓价或强平价作为维持保证金计算口径，结果就可能不同。公式能自洽不等于展示一定清楚；平台需要写明到底用哪一套、何时切档、如何取整。

## 仓位是如何一步步被处理的

![强平后需要核验的数据链路](/assets/liquidation-guide/liquidation-verification-path.svg)

1. **价格输入更新**：指数成分、盘口或资金费率相关数据进入标记价算法。
2. **标记价重算权益**：多头在标记价下跌、空头在标记价上涨时，未实现亏损会吞掉账户权益。
3. **比较维持保证金**：权益低于 `MM`，系统开始撤销占用保证金的委托，并尝试减少或平掉仓位。
4. **市场处置优先**：合理的顺序通常是先在订单簿中处理仓位；能以不差于破产价的结果完成，就不会需要把损失外溢。
5. **处理破产缺口**：若实际平仓比破产价更差，会形成缺口。风险基金、后备流动性或清算池承担的是这段缺口，不是把已亏损仓位“赔回原样”。
6. **最后才是 ADL**：当合约对应的风险基金 / 后备能力不足，平台可能按规则自动减掉盈利且高杠杆的相反方向仓位，以恢复账面平衡。

这条链路有一个边界：**风险基金充足，不等于你的原仓位不会被强平；它通常只用于破产价与实际清算结果之间的缺口。** 但若平台要启动 ADL，就应能证明为什么当时对应资金池、对应合约类别与可接管能力不足。

## 第一类最难接受的情形：插针、维持保证金不足与没有阶梯

![插针、标记价与维持保证金核验图](/assets/liquidation-guide/scenario-wick-and-margin.svg)

一个用户看到的画面往往很简单：某一瞬间价格插针，仓位被平；随后价格回来。真正要拆开的却有三层。

### 插针触发的，到底是最新价还是标记价？

如果平台只用单一市场的最新成交价做清算，薄盘口或异常成交会放大插针风险。更常见的防护是让标记价参考指数价、盘口基差和时间窗口。Hyperliquid 的公开文档也明确写明，其清算使用结合外部中心化交易所价格与自身盘口状态的标记价，而不是单一瞬时盘口价格；其预估强平价也会随资金费用、全仓其他仓位和流动性变化而偏离。([官方清算说明](https://hyperliquid.gitbook.io/hyperliquid-docs/trading/liquidations))

这不代表“标记价一定不会错”。合理的核验问题是：

- 当时使用了哪些指数源？每个源的价格、权重、时间戳是什么？
- 某个源异常、停机、偏离时，剔除还是限幅？采用了什么回退价？
- 标记价的移动平均窗口、采样频率与上限是多少？规则版本是否在事件前后变更？
- 强平触发时的 `Pm`、`Pi`、账户权益、维持保证金和手续费预留，是否能逐项复算？

### 为什么阶梯维持保证金不是“可有可无”

同样是 10 倍杠杆，小仓位和数百万名义价值仓位对盘口的冲击、可平性与尾部风险完全不同。阶梯维持保证金的意义，是让名义价值越大、维持保证金要求越高，而不是让大仓位永远套用小仓位的低阈值。

本地公式资料给出的通用写法是：

```text
本档速算额 = 前一档上限 × (本档维持保证金率 - 前档维持保证金率) + 前档速算额
MM = 仓位价值 × 本档维持保证金率 - 本档速算额
```

没有阶梯本身不必然证明平台不公平；但如果平台允许大额仓位、高杠杆、薄流动性，同时又没有清晰的风险限额、分档表、最大持仓和减仓规则，用户就无法预估自己会在哪个阈值被接管。这是机制透明度问题。

### 你应该保存的证据

| 事件前后 5 分钟应保存 | 用来判断什么 |
| --- | --- |
| K 线与逐笔成交、盘口快照 | 插针是否只出现在单一市场 / 单一薄盘口。 |
| 指数价、标记价、资金费率的逐秒或逐档记录 | 触发是否由标记价而非最后成交价造成。 |
| 风险限额与维持保证金档位截图 / API 响应 | 仓位是否跨档，以及跨档后阈值如何改变。 |
| 账户权益、保证金、未实现盈亏、手续费、强平单与成交回报 | 是否能复算出触发条件和最终损失。 |

## 第二类最难接受的情形：ADL 与“风险基金看起来没有用”

![风险基金与ADL自动减仓处理图](/assets/liquidation-guide/scenario-insurance-fund-adl.svg)

ADL（Auto-Deleveraging，自动减仓）最伤人的地方在于：你本来是盈利的一方，却可能被系统以规则指定的价格强制减少仓位。它不是普通止盈，也不是用户主动成交。

主流平台公开规则通常把它放在靠后位置。例如，[Binance 的风险基金说明](https://www.binance.com/en/support/faq/detail/360033525371)写明，风险基金用于覆盖破产仓位的缺口；当特定合约类别对应资金池无法继续接管时，才会启动 ADL。Bybit 也将风险基金定义为降低 ADL 发生概率的缓冲，只有基金不足以覆盖破产后的负权益，才由 ADL 承接。([Bybit 风险基金说明](https://www.bybit.com/en/help-center/article/Insurance-Fund))

因此，看到一个很大的“风险基金总余额”并不能直接推出“这次 ADL 不合理”。至少还有四个不能跳过的问题：

1. 展示的是不是**同一类合约、同一保证金币种、同一个资金池**？很多平台并非一个总池覆盖所有合约。
2. 余额是日更、小时更还是事件时实时？展示余额与触发瞬间可能不是同一时点。
3. 资金池余额之外，是否还存在最大接管名义价值、流动性容量或单市场限额？Binance 公开说明就提到不同资金池可接管名义价值存在上限。
4. ADL 执行前，平台是否已经尝试订单簿平仓、后备流动性或基金接管？这些步骤的订单、成交、基金变动应能回放。

真正能让用户接受的，不是“相信基金很大”，而是一份可核验的事件记录：**对应池余额、触发前后变化、破产缺口、接管上限、ADL 队列规则、被减仓的数量与价格**。

| 用户看到 ADL 后该问什么 | 合理的公开证据 |
| --- | --- |
| 为什么轮到我？ | ADL 排名因子、触发时的队列档位、你的有效杠杆与盈利率。 |
| 为什么基金没有先兜底？ | 对应资金池而不是总余额；接管容量、可用余额和已承担缺口。 |
| 为什么这个价格减仓？ | 对手方破产价、结算公式、减仓数量与成交 / 结算记录。 |
| 规则有没有临时调整？ | 生效时间、版本号、公告和事件前后的完整参数。 |

交易前也应把 ADL 指示器当作风险变量，而不是装饰。OKX 的接口文档将 ADL 指示器明确分为 0—5 档，数值越高代表在基金不足时越靠前；其说明同时指出高未实现盈利与高杠杆都会提高优先级。([OKX API 文档](https://www.okx.com/docs-v5))

## 第三类最敏感的情形：用户怀疑标记价被“做出来了”

![标记价争议的K线与审计链路图](/assets/liquidation-guide/scenario-mark-price-audit.svg)

这类怀疑不能靠情绪判断，也不能因为“平台说算法没问题”就结束。要区分三个概念：

- **异常行情**：外部现货 / 指数源本身已被薄流动性、操纵或数据故障影响。
- **规则内的标记价偏离**：标记价为防瞬时插针而故意不同于最新成交价；这并不天然不合理，但必须可解释。
- **不可核验或事后改变的价格**：若平台无法给出当时输入、计算、规则版本与事件日志，争议就无法被独立验证。

Hyperliquid 的公开 Oracle 文档说明，验证者会定期提交预言机价格，且预言机价格会参与标记价、保证金、强平与止盈止损；其来源与权重写在文档中。([Oracle 机制](https://hyperliquid.gitbook.io/hyperliquid-docs/hypercore/oracle)) 这正好说明，标记价不是一个“只要显示出来就可信”的数字，它必须能追到输入源与计算路径。

2025 年 3 月的 JELLY 事件是一个值得存档的反例：公开资料显示，薄流动性代币的极端波动和清算仓位接管，最终触发了合约下架与指定价格结算；Hyperliquid 社区 Wiki 也记录了该事件与后续风险参数调整。([事件记录](https://hyperliquid-co.gitbook.io/wiki/introduction/roadmap/incident)) 这件事可以讨论规则、预言机、后备流动性与人工 / 验证者干预的边界，但**不能据此直接认定某个平台“伪造标记价”**。更准确的表述是：当价格来源、风险参数或结算过程无法完整重演时，用户有充分理由要求更透明的证据。

### 一个可执行的标记价争议核验表

```text
统一时区：UTC，精确到秒（高频场景最好到毫秒）
合约与保证金模式：币对、永续/交割、逐仓/全仓、杠杆

1. 逐时点记录：最新价、指数价、标记价、资金费率、盘口中间价
2. 记录指数成分：来源、权重、剔除 / 限幅 / 回退状态
3. 记录账户状态：权益、维持保证金、风险限额档、手续费预留
4. 记录处置链：撤单、强平单、撮合成交、清算池接管、风险基金变化
5. 记录结算链：ADL 排名、减仓数量、减仓价、最终余额和规则版本
```

如果平台只提供一张“强平通知”而没有这些数据，用户无法区分市场风险、规则风险和系统风险。对于平台来说，可审计的数据链路也是最能减少争议的产品能力。

## 交易前的底线检查：别只看爆仓价

- 选择合约前，打开该合约的**风险限额 / 阶梯维持保证金表**，不要只看最大杠杆。
- 看清是逐仓还是全仓。全仓下，其他仓位的亏损、资金费用和可用余额都会改变本仓的风险。
- 观察标记价与最新价在波动时是否经常偏离，并读清指数价来源和价格保护规则。
- 观察平台是否公开**对应资金池**历史，而不仅是一个总余额数字；确认是否有 ADL 指示器、如何排序。
- 止损应放在你能承担的损失位置，而不是紧贴系统强平价。接近强平时，成交、手续费、资金费和规则切档都会让结果比页面预估更差。
- 低流动性标的、高倍杠杆和大额仓位叠在一起时，任何“理论强平价”都只是估算，不是成交承诺。
