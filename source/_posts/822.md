> **错误现象**  
> `msgget() failed, Error: No space left on device[28]`  
> `Swoole\Server::start(): FactoryProcess_manager_start failed`

很多人在使用 **Swoole** 部署高并发服务时，都会遇到这样一个“看似磁盘满、实际不是磁盘”的诡异错误。  
本文将从 **Linux IPC 是什么** 开始，完整解释问题根因与解决方案。

* * *

## 一、问题现象

服务启动时日志如下：

```text
msgget() failed, Error: No space left on device[28]
create task_workers failed
FactoryProcess_manager_start failed
```

同时可能伴随：

```text
open(xxx.log) failed. Permission denied
```

最终导致：

```text
PHP Fatal error:  Swoole\Server::start(): failed to start server
```

* * *

## 二、这真的是「磁盘满」吗？

❌ **不是磁盘满**

`No space left on device (errno=28)` 在这里并不是指：

-   `/` 分区满
-   `/tmp` 满
-   磁盘空间不足

而是指：

> **Linux 内核中某类资源已经被用光**

在这个场景里，指的是 **IPC 资源**。

* * *

## 三、什么是 IPC？（重点）

### 1️⃣ IPC 是什么？

**IPC（Inter-Process Communication）**  
即：**进程间通信机制**

Linux 提供多种 IPC 方式，用于 **不同进程之间的数据交换与同步**。

* * *

### 2️⃣ Linux 中常见的 IPC 类型

<table><thead><tr><th>类型</th><th>作用</th></tr></thead><tbody><tr><td>Message Queue</td><td>消息传递</td></tr><tr><td>Shared Memory</td><td>高速数据共享</td></tr><tr><td>Semaphore</td><td>同步 / 锁</td></tr><tr><td>Socket</td><td>网络 / 本地通信</td></tr><tr><td>Pipe</td><td>父子进程通信</td></tr></tbody></table>

👉 **Swoole 使用的是 System V IPC：**

-   消息队列（msg）
-   共享内存（shm）
-   信号量（sem）

* * *

### 3️⃣ IPC 和磁盘的关系？

IPC **不是磁盘文件**，而是：

-   存在于 **内核内存**
-   受 **内核参数限制**
-   **进程异常退出不会自动释放**

所以：

-   `df -h` 看不出来
-   但 `msgget()` 可能失败

* * *

## 四、Swoole 为什么依赖 IPC？

### Swoole 的进程模型

```text
Master
 ├── Manager
 │    ├── Worker 1
 │    ├── Worker 2
 │    └── Task Worker
```

进程之间需要：

-   传递任务
-   同步状态
-   共享数据

👉 这些全部依赖 **IPC**。

* * *

### 当 IPC 资源耗尽时

```text
msgget() → 失败
 ↓
Worker 无法创建
 ↓
Server 启动失败
```

* * *

## 五、IPC 为什么会被耗尽？

### 1️⃣ 程序异常退出（最常见）

-   `kill -9`
-   PHP fatal error
-   OOM
-   崩溃未清理

👉 **IPC 对象残留**

* * *

### 2️⃣ 频繁重启服务

-   每次启动都会创建 IPC
-   旧的没释放
-   很快用完系统配额

* * *

### 3️⃣ 内核参数限制过小

关键参数：

```bash
kernel.msgmni   # 消息队列数量
kernel.msgmnb   # 单个队列最大字节
kernel.msgmax   # 单条消息最大字节
```

* * *

### 4️⃣ 容器 / 云环境限制

-   Docker 默认限制 IPC
-   部分云主机限制 SysV IPC

* * *

## 六、如何确认是 IPC 问题？

### 1️⃣ 查看消息队列

```bash
ipcs -q
```

如果看到大量残留队列，基本可以确认。

* * *

### 2️⃣ 查看系统限制

```bash
sysctl -a | grep kernel.msg
```

* * *

## 七、解决方案

* * *

## ✅ 方案一：清理残留 IPC（立刻生效）

⚠️ **生产环境操作前需确认**

```bash
ipcs -q | awk '{print $2}' | xargs -n1 ipcrm -q
```

或按用户清理：

```bash
ipcs -q | grep www-data | awk '{print $2}' | xargs ipcrm -q
```

* * *

## ✅ 方案二：调整内核参数（推荐）

编辑 `/etc/sysctl.conf`：

```conf
kernel.msgmni = 4096
kernel.msgmnb = 65536
kernel.msgmax = 65536
```

生效：

```bash
sysctl -p
```

* * *

## ✅ 方案三：修复日志权限（防止连锁问题）

```bash
chown -R www-data:www-data /opt/weblogs
chmod -R 755 /opt/weblogs
```

* * *

## 八、如何预防？

### ✔ 正确关闭服务

-   使用 `SIGTERM`
-   避免 `kill -9`

### ✔ 定期巡检

```bash
ipcs -q | wc -l
```

### ✔ 统一启动脚本

-   启动前清理 IPC
-   避免重复残留

* * *

## 九、总结

> \*\*Swoole 启动失败并非磁盘问题，而是 Linux IPC 资源耗尽；  
> IPC 是内核级进程通信机制，异常退出会导致资源残留；  
> 清理 IPC + 调整内核参数是根本解决方案。\*\*
